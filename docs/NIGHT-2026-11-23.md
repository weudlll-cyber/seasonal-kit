## Piece 1: back link space

`.sk-back-link` is an inline flex box, so the space after "←" began the text's own box and
collapsed. A `gap: 0.35em` keeps them apart. showcase/layout.spec.ts (new) measures, in Chromium,
the distance from the arrow's box to the words' text box (a Range): 4 px or more. Without the
fix it measures 0 (checked). DECISIONS K32 records that the games' requests go into the kit.

## Piece 3: the header folds when its items do not fit (Bingo R1)

- **`src/react/useHeaderFold.ts` (new):** ported from Bingo's `useBarFold` (5c613c0) without
  its fixed 960 px. Before the paint it folds when an item would start below another's bottom,
  and it remembers the width it folded at. It tries one row again on a new close key and when
  the window grows past that width, and it checks again when the header changes size. The
  first render is unfolded, so a server render reads no `window`.
- **`MenuFold`:** uses the hook, and closes an open panel when the header unfolds again.
- **css/header.css:** the `@media (max-width: 959px)` block is now `.sk-header[data-sk-folded='true']`
  rules. The 960 px bound is gone: the measurement covers it. Phones fold every showcase header,
  and a short bar stays in one row where it fits.
- **Tests:**
  - src/react/headerFold.test.tsx (stubbed boxes): one row, a second row, a new close key, a
    wider and a smaller window, a resized header, unfolding closes the menu;
  - showcase/layout.spec.ts: every header keeps one row at 1280, 1536, 1920 and 390 px; the
    admin bar (new in the showcase: website mode, five links, an admin's chip) folds at
    1280 px; a short bar stays unfolded at 1920 px.

  With the old fold, three of them fail (two rows at 1280 and 1536 px; checked). The whole
  showcase passes 38/38, axe included. Locally the three header files passed (24 tests) before
  the machine's load rose. After that no jsdom test worker started in time, even one file
  alone; the node files passed (307 tests). Timeouts stay as they are, as the brief says, so
  coverage is CI's `verify` on this push.
