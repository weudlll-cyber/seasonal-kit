# Handbook: how we build a Seasonal game

One place for every new game, and for every game that changes. Each rule names where it is
enforced: a CI job (`.github/workflows/ci.yml`), a lint rule (`eslint.config.js`), a test, a
git hook (`lefthook.yml`) or a working rule (`CLAUDE.md`). A rule enforced only by a working rule
is checked in review (`docs/code-review-checklist.md`). This handbook says how to build a game;
how a game is embedded in the website is the website's own docs, linked in the last section.

**Keeping it current.** Every kit release updates this handbook in the same PR where its parts or
rules change (K51, [RELEASING.md](RELEASING.md) step 1). **Every rule names its check.** Where
a test makes no sense, the row says why and that review checks it (K52).

## The first day

From an empty repository to a skeleton whose every check is green before the first game feature.
The template is the newest game that has the files: **Seasonal Cases** (`master` `073f9ad`), read
from its `origin/master`; for what Cases lacks (`.gitleaksignore`, `Dockerfile`, `ops/`) the
later pins are in **Seasonal Mini Games** (`0bed072`).

1. **Protect the repository** as the kit's is: `master` takes changes by pull request only, with
   the checks required and the branch up to date, 0 required approvals (the owner approves and
   merges), conversations resolved, admins included, no force-push, no deletion (K13); the
   showcase's browser run is a required check where the game has one (K19); merge commits only,
   the branch deleted after a merge, `v*` tags immutable, vulnerability alerts on, no wiki and no
   Projects, actions pinned to commit SHAs (K24; the settings as read back are in
   [RELEASING.md](RELEASING.md)).
2. **Copy the skeleton from Cases:** `.github/workflows/ci.yml`, `codeql.yml`, `browsers.yml` and
   `.github/actions/setup`; `lefthook.yml`; `renovate.json`; `eslint.config.js`,
   `prettier.config.js`, `tsconfig.base.json`, `tsconfig.bundler.json`, `tsconfig.json`,
   `vitest.config.ts`, `pnpm-workspace.yaml`; `.editorconfig`, `.gitattributes`, `.gitignore`,
   `.npmrc`, `.nvmrc`, `.prettierignore`, `osv-scanner.toml`; `LICENSE`, `CLAUDE.md`,
   `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, and `docs/DECISIONS.md`, `docs/BACKLOG.md`
   and `docs/OPEN.md`.
3. **Pin the kit by tag** in `package.json` (see "The repository and the kit"), and take the
   stylesheets and parts the game uses from it.
4. **One first PR** carries the skeleton; it merges when every required check is green and the
   owner has approved. Cases' `pnpm verify` (format check, lint, typecheck, test and the kit's
   version check) is the one command that must pass before every report.

## The repository and the kit

- **Layout.** A game keeps its web client, its server and its shared contracts apart (Mini Games
  and Bingo: `apps/web`, `apps/server`, `packages/contracts`). Every source file starts with its
  header (see Hygiene).
- **The kit pin.** A game depends on the kit by tag, never by branch:
  `"@seasonal/kit": "github:weudlll-cyber/seasonal-kit#vX.Y.Z"` ([README](../README.md)). Its
  lockfile pins the tag's commit and its hash, so a moved tag would fail the install. Tags never
  move ([RELEASING.md](RELEASING.md)). A game moves to a new version in its own PR, with the
  owner's word (K1), following the CHANGELOG's "Migration, per game".
- **The package says what it may drop.** `"sideEffects": ["**/*.css"]`: a bundler may drop unused
  JavaScript and always keeps a stylesheet a game imports (K58, `tests/package.test.ts`, and the
  delivery proof bundles a consumer).
- **No install scripts.** The kit ships its compiled `dist/`; a game installs with scripts off
  (`ignore-scripts=true`) ([DELIVERY.md](DELIVERY.md)). Enforced: CI `verify` ("dist/ matches
  the source") and the delivery proof on every tag.
- **A part the kit lacks** is a stand-in: built as small as possible, under its own folder
  (Seasonal Cases' `packages/ui/src/pending/`), with a header line naming the kit BACKLOG item it
  waits for and a row in the game's BACKLOG as an adoption item, and removed when the kit has it:
  the move to that kit version is a dated decision of the game (Cases D40) that replaces every
  stand-in the kit now has ([ADOPTION.md](ADOPTION.md), "Seasonal Cases"; Cases' CLAUDE.md "The
  kit"). Never a second copy of a kit part. Enforced: review. No test can tell what the kit
  "could hold"; the CHANGELOG's "Migration, per game" names the stand-ins a release replaces.

## The kit parts every game uses

The exports are in the [README](../README.md); what each replaces per game is in
[ADOPTION.md](ADOPTION.md); the release of each addition is in the [CHANGELOG](../CHANGELOG.md).
Each part is held by its own tests in `src/` and `tests/` and by the showcase (CI `showcase`).

- **Header:** `AppHeader` with `BackLink` in website mode; folds into its Menu whenever its items
  do not fit, or always under `foldBelow` px (K40, `header.css`). The theme toggle is always
  last in the row; there is no configurable order (K43). `account.steps` draws the member's
  website step badges as small icons in the chip, only for the website's own icon addresses
  (K56).
- **Game bar:** `GameBar` with `usePanels`, `useFullscreen`, `useFocusMode`, its toggles
  (`bar.css`); `back` puts the back link first (K39); the `prefs` icon; `presses` for a button
  that only sends a press (`applaud`); a panel button may name its panel with `controls`
  (`aria-controls`, K58).
- **Dock and chat:** `DockedScreen`, `ChatDock`, `WebsiteChatFrame` (`dock.css`); `withoutChat`
  for a screen with no dock (it still follows the keyboard); `useDockSight` for a game's own
  frame in the dock; `useOpenDockChat` to open the chat from the game; `useDockReserve` without a
  chat; `onUnread` for the bar's count. On a phone the open sheet is never taller than the
  space visibly left above the bar (K50): the game's root is `var(--sk-visible-height, 100dvh)`
  high, and the head and the bar stay visible.
- **Call slot:** `callSlot`, `CALL_SLOT` (`call.css`). With a call id the dock's slot frames the
  website's call view (`CallFrame`, `callEmbedUrl`; K44) and follows its size; with none it takes
  no room.
- **Fit floors:** `useFitScale` and `fit.css` with the game's `data-sk-game`; `MIN_POINTER_TARGET`;
  `afterFonts` fits again once web fonts have loaded, on `useFitScale` and, through its `fit`
  prop, on `StartCard` (K48) and on a `fitted` `ResultFrame` (K55); a default text floor in `tokens.css` for a game with no `fit.css`
  (K41).
- **Result frame and start card:** `ResultFrame` (a page, or a `panel`) and `StartCard`
  (`frames.css`). With no `reveal` the frame has no reveal box and one column; an optional
  `middle` card sits between the first part and "more" (K42). There is no merged single-card
  option: every game shows its result the same way, and Bingo drops its own overrides (K47).
- **Sign-in:** the website sign-in in the client (`websiteSignInHref`, `signInAgain`) and on the
  server (`websiteSignInCheck`, `safeNext`, TOTP, recovery codes, `SessionEnds`).
- **Failure brake:** `FailureBrake` for the failed tries of a sign-in, in every game (K46); the
  rules and keys stay in the game.
- **Rate limiter:** `RateLimiter` with the game's own rules, for the routes other than sign-in.
- **Backups:** `ops/backup.sh` (backup, restore, drill, the nightly timer's units) and the pull scripts,
  shipped in the package and set by `SK_BACKUP_*` variables (K61, [OPERATIONS.md](OPERATIONS.md)); the
  game wires them and keeps its own compose files and key checks.
- **Open-rounds publisher:** `openRoundsPage` behind the game's `GET /api/public/open-rounds`.
- **Season feed:** `seasonFeedReader` with `guardedFetch({ allowedHosts })` or the game's own (K62).
- **Test tools** (K66): `@seasonal/kit/testing`, for a game's own suites only: `setTheme`,
  `captureLook`, the sizes, and the guards `findFixedColours`, `findSmallText` and `findLowContrast`.
- **Phone layouts** (K65): the folded header's brand keeps its longest word, the back link's words wrap,
  the game bar's facts wrap and its buttons keep a row, with the gutter tokens' padding;
  `StartCard` without `opensIn` has no countdown. Measured in `showcase/cases.spec.ts`.
- **Session cookie, CSRF, headers:** `sessionCookie` (lifetime = the session's absolute length), `writeCheck`
  (a write names where it came from; the forwarded host only from the proxy) and `securityHeaderSet` (K60,
  K63); the game keeps its token, its session store and the admin path test.
- **Health routes:** `/healthz` and `/readyz` (`HEALTH_PATHS`), the readiness answer from `readiness`
  (K64); the game limits the routes per address and owns the probe.
- **Guarded fetch:** `guardedFetch` and `isPublicAddress` for every call a server makes to an address
  it was handed (K62).

## Embedding in the website

A game runs standalone and, once embedded, under `/games/<slug>/` on the website's origin: the
website signs its members in, frames its chat, lists its open rounds and publishes the season.
How a game is added and what the two sides exchange is the website's to say, and is not copied
here:

- [ADDING-A-GAME.md](https://github.com/weudlll-cyber/seasonal-entertainment/blob/master/docs/ADDING-A-GAME.md):
  what a game provides, what changes in the website, what an admin and the installer do, and
  the checklist.
- [GAME-INTEGRATION.md](https://github.com/weudlll-cyber/seasonal-entertainment/blob/master/docs/GAME-INTEGRATION.md):
  the sign-in headers, the chat embed, the back link, the call slot and the season feed.

## Glossary

| Word                            | Meaning, and where it is defined                                                                                                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ST**                          | Seasonal Tokens, the project the website is for (website README); the website's seed media call its logo and intro "ST" (`server/seeds/chat-media/README.md`). The kit's font belongs to it ([fonts/README.md](../fonts/README.md)). |
| **The four seasons**            | Spring, Summer, Autumn and Winter: the four tokens, each with a colour the website owns (`--sk-color-spring` … `winter` in [tokens.css](../css/tokens.css), K3; the website's `docs/DESIGN.md`, "Token colours").                    |
| **Season**                      | The token with the highest current reward, in lower case (`spring` … `winter`) (website `docs/GAME-INTEGRATION.md`, "Season feed").                                                                                                  |
| **Season feed**                 | The website's public `GET /api/public/season`: `inSeason` and the `halvingDays`, read server to server through `seasonFeedReader` (website `docs/GAME-INTEGRATION.md` §6; K34).                                                      |
| **Website mode and standalone** | Two kinds of install: website (embedded in the website, players sign in with their website account) and standalone (the game's own accounts) (Bingo's `docs/PRIVACY-DATA.md`).                                                       |
| **Slug**                        | A game's short name in lower case, digits and single hyphens; it makes its path `/games/<slug>/` (website `docs/ADDING-A-GAME.md`).                                                                                                  |
| **Open rounds**                 | The optional page a game serves at `/games/<slug>/api/public/open-rounds`, which the website reads to list rounds open for sign-up (website `docs/OPEN-ROUNDS.md`; the kit's `openRoundsPage`).                                      |
| **The dock**                    | The chat under a game's screen: a strip on a desktop, a bar with a sheet on a phone (`DockedScreen`, [dock.css](../css/dock.css)).                                                                                                   |
| **The call slot**               | The place in the dock reserved for the website's call view (K6, K44; [call.css](../css/call.css)).                                                                                                                                   |
