## Piece 3: the header folds when its items do not fit (Bingo R1)

- **`src/react/useHeaderFold.ts` (new):** ported from Bingo's `useBarFold` (5c613c0) without
  its fixed 960 px. Before the paint it folds when an item would start below another's bottom,
  and it remembers the width it folded at. It tries one row again on a new close key and when
  the window grows past that width, and it checks again when the header changes size. The

## Piece 5: the open-rounds publisher

- **`src/server/openRounds.ts` (new, `/server`):** `openRoundsPage(rounds, { origin, now?, onDrop? })`
  and `OPEN_ROUNDS_CACHE_CONTROL`. Read from the website's docs/OPEN-ROUNDS.md and
  `openRoundsContract.js` (d4230af), and from the three games' builders:
  - Bingo master c1bab70;
  - Mini Games master 21434d8 (`feat/open-rounds` is merged and gone);
  - Cases proto/cases-v1 cc75504.
- **What the website pulls:** each game serves a public GET that the website polls every 60 s;
  nothing is pushed and no secret is involved. So the kit builds the page and the game keeps
  its route.
- **Fitting all three:**
  - a `Date` or a UTC string (Bingo, Mini Games);
  - title and kind cut, never through an emoji (Bingo cut titles; Mini Games' kinds reach 43);
  - ids never cut;
  - the same-origin https `joinUrl` checked (Cases' local `http` would be dropped, as the
    website drops it);
  - at most 20 after the check, where the site counts before it, so a broken entry takes no
    place (Bingo's limit setting goes up to 100).
- **Tests:** src/server/openRounds.test.ts: each website rule and its drop reason, the cut, the
  cap after the check, no unknown field, and each game's round shape. 100 % of the file.
